## Slide 2 — Proposed Solution

**The problem, in one line**
- A compliance audit joins two things that share no vocabulary: a config in a
  **vendor's grammar** and a benchmark written in **prose about concepts**.
- Naive designs couple them directly → 4 frameworks × 8 vendors = **32 parsers**.

**Our solution: a canonical fact model between them**
- Config → pattern pack → **330 canonical paths** → rules → findings → signed PDF
- A fact is `(path, value, provenance)`. Rules are written against **paths, never
  syntax**.
- New vendor = **a YAML file**. New benchmark = **a YAML file**. Zero engine code.

**What is genuinely novel**
- **The AI teaches the parser; it never decides a verdict.** Unrecognised lines
  escalate through 3 tiers, an operator confirms once, and the mapping becomes a
  *deterministic pattern* — hot-reloaded, **no redeploy**.
- **`notchecked` is a first-class verdict.** Score = `pass / (pass + fail)`, so
  coverage can never be improved by declining to check something. All **22**
  unautomated controls are argued individually in `docs/GAPS.md`.
- **Every claim is regenerable.** One command re-measures every published number;
  the test suite fails when one goes stale.
- **Fully offline.** One Python process, no cloud, no API key — deployable on an
  air-gapped assessor's laptop.

**Working prototype, not a concept** — **1,798** tests passing; 20 device configs
ship with it.

## Slide 3 — Technical Approach

**Stack:** Python 3.10 · FastAPI · SQLite · ReportLab · Ed25519 ·
scikit-learn / SetFit / llama.cpp (all optional) · **dependency-free ES modules**
frontend, 10 views, **no build step**

```
config text ──▶ pattern pack ──▶ canonical facts ──▶ rules ──▶ findings ──▶ PDF
                (YAML/vendor)     (330 paths)        (YAML)      │           │
                     │                                          │           │
               unparsed lines                            projection   hash-chained
                     │                                    (NIST/ISO)     ledger
                     ▼                                                      │
        AI tiers 1→2→3 ──▶ Training GUI ──▶ new pattern ────────────────────┘
      (tfidf/SetFit/LLM)   (operator confirms)   (hot-reloaded, no restart)
```

**Measured, on an i5-13500H laptop**

| Stage | Result |
|---|---|
| Vendor detection | **20 / 20** fixtures, by content not filename |
| Parse coverage | **98.7%** of significant lines · 4,302 facts · p50 **8.2 ms** |
| Rule evaluation | **454** rules over **42** catalogs / **3,366** controls · p50 **8.4 ms** |
| CIS Cisco IOS 15 | **71 / 90** controls automated |
| DISA STIG IOS NDM | **32 / 35** controls automated |
| DISA STIG NX-OS NDM | **39 / 42** controls automated |
| Per-device PDF | 124–200 KB · p50 **0.80 s** |
| Fallback renderer | pure-Python, **72.1× faster**, same verdicts, same hash |

**Two frameworks direct, two projected** — CIS and DISA STIG are evaluated
against facts; NIST SP 800-53 and ISO 27001 are projected through the
**publishers' own crosswalks** (DISA ships CCI → NIST for every control).
Projected verdicts are **labelled as projected**: a roll-up is weaker evidence
than a measurement.

## Slide 4 — Feasibility and Viability

**Feasible — it already runs**
- 1,798 tests · ruff clean · every metric regenerated by one command
- Runs on a 16 GB laptop, **no Docker, no GPU required**, no network
- Setup is two commands; `python scripts/serve.py` is the whole deployment

**Risk 1 — the AI hallucinating a canonical path.** Real, and we hit it.
- Tier 1's calibrated softmax reports *P(class | it is one of my classes)* — it
  cannot say "this is not a config line". Result: **0.929 for `shutdown` and
  0.929 for `zzzzzzzz qqqq`**, above the τ=0.85 gate. It answered **28 of 51**
  lines with the same class, including for a shopping list.
- **Found by a negative control we built to try to break it**, not by a user.
- **Fixed** by comparing each prediction against the model's unconditional prior
  and abstaining below a margin. Abstention on non-config input: **1.00**.
  Suggestions outside the 330-path schema: **0**.
- **Lesson:** a confidence threshold bounds how sure a model *claims* to be, not
  whether the question was in its domain.

**Risk 2 — one vendor shipped.** Cisco IOS today.
- Mitigated by design, not by promise: a vendor is a data file, so the next one
  costs a pattern pack. The DISA STIG pack — 34 catalogs, 32 rules, 3
  previously-dark frameworks — needed **zero lines of engine code**.

**Risk 3 — plain HTTP.** Identity was the top item here and is now built: three
ordered roles on every route, PBKDF2 passwords, and the operator's name *inside*
the signed audit record rather than beside it. What remains is transport — the app
implements no TLS and will not; `deploy/nginx/praman.conf` is the config, not a
promise. Binds loopback by default, and says why when you override it.

**Risk 4 — quoting a flattering number.** Coverage is **13.49%** of *all* loaded
controls and we publish that, because most catalogs are for platforms no pattern
pack covers yet. No accuracy figure is claimed for the classifier: there is no
hand-labelled ground truth in the repo, so the number would not be defensible.

## Slide 5 — Impact and Benefits

**Who it is for**
- Security-sensitive network operators auditing estates **offline, air-gapped**
- Enterprise NOC/SOC teams under CIS / STIG / ISO 27001 obligations
- Auditors who must **re-verify a report months later** without trusting the tool

**Impact**
- A manual per-device audit against 90 CIS controls is **hours**; PRAMAN decides
  454 rules in **8.4 ms** and produces the signed report in **~1 s**
- **One parse, four frameworks** — the same evidence answers CIS, STIG, NIST and
  ISO instead of four separate audits
- **Every failure ships the publisher's own fix CLI**, extracted from their
  `fix_text` and **never generated** — an auditor acting on a hallucinated
  command is the failure mode that makes tools like this dangerous
- **Unknown formats stop being a dead end.** An operator maps a line once in the
  GUI and the parser knows it permanently — no vendor ticket, no redeploy

**Why the output is evidence**
- Every audit is **hash-chained and Ed25519-signed**; findings commit through a
  **Merkle root**; the PDF carries `X-PRAMAN-Record-Hash`
- `/audit/verify` re-reads rows from SQLite and re-checks **four independent
  links per record**, so tampering with any earlier record invalidates every one
  after it — the report is checkable **without trusting the process that made it**

**Economic / operational**
- Zero licence cost, zero cloud spend, no per-device agent
- Sensitive configs **never leave the operator's machine**
